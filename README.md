# dcgen — devcontainer generator

`dcgen.py` generates a `.devcontainer/devcontainer.json` by interactively picking
features from a curated catalog. Single file, **Python stdlib only** — no pip
dependencies, runs on any host with Python 3.8+ (the checkbox UI uses `curses`
on POSIX terminals and falls back to numbered prompts everywhere else).

Companion docs:

- [`CATALOG.md`](CATALOG.md) — what's in the catalog right now: features, apt
  groups, addons, presets, and the collated MCP server inventory.
- [`AGENTS.md`](AGENTS.md) — the fine print for coding agents: catalog schema,
  generation/sync semantics, pi-state rules, verify normalization.

```
agent-builder/
├── dcgen.py         # the tool (self-contained)
├── catalog.json     # feature catalog + presets (edited, not generated)
├── CATALOG.md       # catalog inventory
├── AGENTS.md        # agent-facing rules and invariants
├── TODO.md          # deferred design work
├── features/        # local features (one dir per feature, installed into targets)
└── pi-master/       # master copy of .devcontainer/pi
```

This repo **self-hosts**: its own `.devcontainer/` is generated by running
`python3 dcgen.py --preset agent-builder`.

Local features live in `features/` (one dir per feature) and are copied into the container
configuration at generation time, rather than requiring them to be published.

## Usage

Run **from the directory you want to generate into**.

```bash
python dcgen.py [<options>] [<target>]
```

| Option | Meaning |
|---|---|
| `target` (positional) | target repo dir, default `.` |
| `--preset NAME` | non-interactive generation from a catalog preset |
| `--refresh` | re-apply the preset matching this devcontainer, no prompt; error if no match |
| `--name` / `--image` | override project name / base image |
| `--catalog PATH` | alternate catalog (default: `catalog.json` next to the script) |
| `--features-repo PATH` | override features dir location |
| `--list` | print features, apt groups, addons, presets |
| `--dry-run` | print everything (config + planned copies) without writing |
| `--verify JSONFILE` | compare a config (from `--preset`, `--refresh`, or the wizard) against an existing devcontainer.json |
| `--show` | show the selected configuration as a catalog.json preset entry (no write) |
| `--sync-features` | refresh `./`-referenced local features in target (in place) |
| `--sync-pi` | sync `pi-master/` into `<target>/.devcontainer/pi` (copy-if-older, state-safe) |

Exit codes: `0` ok · `1` usage/catalog error · `2` verify differences.

Interactive input can be interrupted safely: EOF/Ctrl-C at any prompt aborts
without writing.

## Examples

```bash
python3 dcgen.py                        # interactive wizard
python3 dcgen.py --list                 # dump catalog contents
python3 dcgen.py --preset agent-builder # non-interactively generate from the "agent-builder" preset
python3 dcgen.py --preset worker --verify .devcontainer/devcontainer.json # Diff an existing devcontainer.json against the preset "worker"
python3 dcgen.py --preset myproject --dry-run # Show what would be created for the "myproject" preset but do not write.
python3 dcgen.py --show                 # Run the wizard and show the selected config as a catalog.json preset.
python3 dcgen.py --refresh              # refreshes current config from detected preset, no prompts
python3 dcgen.py --sync-pi              # refresh ./.devcontainer/pi from pi-master
```

## What the wizard asks

0. Offers to refresh a pre-existing configuration if it matches a known preset.
1. Project name (default: directory name) and base image (default: catalog's).
2. **Language runtimes** — checkbox list. Locked features are *not* shown;
   they are always included.
3. **Tool features** — local features from `features/`.
4. **apt package groups** — logical groups that merge into one deduplicated
   `apt-packages` entry (locked groups are always on). Afterwards: free-text
   extra packages, then extra workspace mounts (one per prompt; a bare host
   path targets `/workspaces/<basename>`).
5. **Environment addons** — runArgs / mounts / containerEnv /
   postCreateCommand fragments. Conflicting selections warn;
   unselected recommendations are noted.
6. Option prompts for selected features that define them.
7. Review summary → confirm → generate.
8. Offer to save the configuration as a preset in `catalog.json`

Selection menus show a one-line description per item; items marked `(h)`
carry a longer help text — press `h` (or `h <number>` in the plain fallback).

## pi config (`.devcontainer/pi`)

This tool is primarily intended for managing instances of the Pi coding agent,
so it currently forces the pi feature on for each container.

`.devcontainer/pi` is bind-mounted as `~/.pi`, so after first boot it is
runtime state: generation bootstraps it from `pi-master/` only when it is
missing or empty, and never touches an existing config. `--sync-pi` is the
explicit, state-safe updater.

## Verifying / migrating existing repos

Use the following to compare an existing configuration against a preset:

```bash
python3 dcgen.py --preset <name> --verify .devcontainer/devcontainer.json
```
